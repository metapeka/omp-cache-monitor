# Upstream: `group` / `icon` для настроек плагина

Статус: предложение заведено — <https://github.com/can1357/oh-my-pi/issues/20253>
(OMP 19.1.1, 2026-11-23).

## Проблема

`package.json` → `omp.settings` рендерится плоским списком: у плагинных
настроек нет групп, заголовков и иконок. У core settings они есть. Плагин с
15 ключами (`omp-cache-monitor`) кодирует группы префиксами
`Preset ·` / `Status ·` / `Warnings ·` / `Reports ·` в каждом `description`;
это работает, но заголовков в панели всё равно нет.

## Предложение

Необязательные поля презентации у каждого ключа:

```json
{
  "omp": {
    "settings": {
      "preset": {
        "type": "enum",
        "default": "balanced",
        "group": "Preset",
        "icon": "🎛",
        "description": "Value bundle for the other keys."
      },
      "statusEnabled": {
        "type": "boolean",
        "default": true,
        "group": "Status",
        "icon": "⚙",
        "description": "Show hit rate in the status line."
      }
    }
  }
}
```

Правила:

- ключи с одинаковым `group` идут под одним заголовком;
- порядок групп — первый встреченный ключ (или явный `order`);
- `icon` необязателен; без него заголовок текстовый;
- ключи без `group` сохраняют текущий плоский вид;
- парсинг, defaults и валидация не меняются; старые манифесты рендерятся
  как раньше.

Альтернатива — отдельный `settingsGroups` с `id`/`title`/`icon` и
`group: "<id>"` у ключей.

## Что это даёт

- Авторам плагинов не нужен обходной путь с префиксами в `description`.
- Пользователь быстрее находит нужный ключ в длинном списке.
- Обратная совместимость: отсутствие полей = текущее поведение.
